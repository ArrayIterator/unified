# Sub-module icons

Date: 2026-11-23. Status: IMPLEMENTED (task 371).

## What counts as a sub-module

There is no sub-module registry, submenu, or parent/child concept in the module system (`Module` trait, `ModuleInfo`, admin menu) — that was established by grep before collecting. The only "sub-modules" in the codebase are Rust `mod` declarations. So a sub-module here is a **distinct Rust `mod` name declared inside a module root file** (`src/modules/<module>.rs`), plus 11 names that only appear in deeper declarations (`src/modules/*/*.rs`). The 153 declarations in `src/modules/mod.rs` are the top-level modules themselves, not sub-modules, and are excluded.

## Counts

- **582 sub-module names** total (571 from module roots + 11 deeper-only).

- 271 `handlers_*` (handler groups per feature), 10 `adapters_*`, 301 other names.

- Mapped to **186 distinct Tabler icons** (+ 1 custom reuse: `handlers_balancers` reuses the custom `load-balancer` drawing). Names that share a concept share an icon — internal code files are not user-visible concepts, so forcing 582 globally unique icons would mean assigning random icons to fill slots, which violates the common-and-correct rule.

- Rule applied: common and correct only — the obvious, mainstream metaphor for the concept; suffix-based for `handlers_*` / `adapters_*` (the icon pictures the feature, e.g. `handlers_accounts` → `users`).

## Files

- Icons: `assets/icons/submodules/<name>.svg` (one file per name).

- Sprite: `assets/icons/submodules-sprite.svg`, built by `python3 scripts/build-submodule-icons-sprite.py` (582 symbols, `submodule-icon-<name>`).

- Preview: `assets/icons/SUBMODULES.md`.

- No UI consumes sub-module icons yet — this is a collection for future use (admin sub-menus, module detail pages).
